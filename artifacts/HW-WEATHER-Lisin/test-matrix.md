# Матрица тестов

## Unit-тесты

- Comparator ранжирования риска:
  - `LOW` лучше `MEDIUM` и `HIGH`;
  - `MEDIUM` лучше `HIGH`;
  - равный риск сравнивается по меньшему количеству факторов;
  - полное равенство сравнивается по более раннему старту.
- Генерация кандидатов:
  - стартует с первого полного часа не раньше `search_start`;
  - конец кандидата должен помещаться в `search_end`;
  - отсутствие кандидатов возвращает контролируемую ошибку входа;
  - неполные границы обрабатываются детерминированно.
- Валидация времени:
  - невалидная дата отклоняется;
  - прошлый интервал отклоняется;
  - `search_end <= search_start` отклоняется;
  - `search_end > now + 5 days` отклоняется;
  - duration должно быть целым числом 1..8.

## Тесты сервиса

- Успешный поиск делает один geocoding-запрос и один forecast-запрос.
- Неизвестный город возвращает `not_found` и не запрашивает forecast.
- Неоднозначный город возвращает варианты и не запрашивает forecast.
- Некорректный forecast, HTTP-ошибка, timeout, битый JSON и отсутствующий час выбрасывают контролируемый `WeatherDataError`.
- Forecast-часы покрывают весь интервал поиска, нужный для сгенерированных кандидатов.

## MCP-тесты

- `listTools` содержит `get_weather`, `assess_weather_risk`, `compare_weather_windows` и `find_safe_weather_window`.
- Успешный ответ содержит совпадающие JSON-текст и `structuredContent`.
- Сбой Open-Meteo имеет `isError: true` и не содержит частичный `structuredContent`.
- Существующие инструменты сохраняют прежнее поведение.

## Ручная проверка после реализации

- Запустить `npm run ci`.
- Запустить MCP Inspector через `npm run inspect`.
- Вызвать `find_safe_weather_window` с успешным примером для Dubai.
- Вызвать инструмент с невалидным или неоднозначным городом и зафиксировать контролируемый отказ.
