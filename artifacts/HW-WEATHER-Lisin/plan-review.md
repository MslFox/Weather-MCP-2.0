# Review плана

Роль: Critic

## Вердикт

Нужны правки перед реализацией. План v1 в целом выбран правильно, но до изменения кода нужно явно зафиксировать несколько граничных случаев.

## Замечания

1. Для случая без кандидатов нужна явная контролируемая ошибка.
   Если `duration_hours` длиннее интервала поиска или полные часовые старты не дают подходящего окна, инструмент должен вернуть ошибку входа до запроса погоды.

2. Нужно явно описать правило полного часа.
   Требование говорит, что кандидаты начинаются каждый полный час, но не говорит, что `search_start` и `search_end` сами обязаны быть полными часами. План должен определить: кандидаты стартуют с первого полного московского часа не раньше `search_start` и продолжаются, пока конец кандидата не позже `search_end`.

3. Пятидневное ограничение нужно привязать к концу интервала.
   Существующий `parseWorkPeriod` проверяет `end <= now + five days`. Новый интервал должен требовать `search_start >= now`, `search_end > search_start` и `search_end <= now + five days`.

4. Требование одного forecast-запроса легко случайно нарушить.
   В плане нужно явно запретить вызов `OpenMeteoRiskService.assess` для каждого кандидата.

5. Порядок альтернатив должен быть детерминированным.
   План должен указать, что альтернативы — это следующие кандидаты после выбранного в отсортированном списке, максимум три.

6. Тесты должны считать запросы прогноза.
   Нужен отдельный тест, который подтверждает один geocoding-запрос и один forecast-запрос при успешном поиске.

7. В форме ответа нужен конец кандидата по московскому времени.
   Предложенная форма уже содержит `end_at`, но критерии приёмки должны сделать его обязательным, потому что клиенту нужно полное выбранное окно.

## Рекомендованные изменения для v2

- Добавить явные правила валидации интервала и кандидатов.
- Добавить контракт comparator-а ранжирования.
- Добавить тесты для отсутствия кандидатов, неполных границ поиска, tie-break по числу факторов и одного forecast-запроса.
- Сохранить строгую границу между артефактами планирования и реализацией до одобрения пользователя.
