# Анализ влияния

## Публичная поверхность

Изменение добавляет один MCP-инструмент: `find_safe_weather_window`.

Имена, входы и семантика существующих инструментов должны остаться прежними:

- `get_weather`
- `assess_weather_risk`
- `compare_weather_windows`

## Затрагиваемые компоненты

- `weather-mcp/src/index.ts`: регистрация нового инструмента и преобразование результатов сервиса в MCP-ответы.
- `weather-mcp/src/open-meteo.ts`: вероятно, новый batch/search-метод и общие helper-функции для геокодирования и hourly-прогноза.
- `weather-mcp/src/time.ts`: вероятно, парсинг интервала поиска и helper-функции полного часа.
- `weather-mcp/src/risk.ts`: только переиспользование, без изменения порогов.
- `weather-mcp/test/*`: тесты нового инструмента и регрессии старых.
- `weather-mcp/README.md`: документация нового инструмента.

## Риски регрессии

- Изменение приватных helper-функций в `open-meteo.ts` может повлиять на `assess_weather_risk` и `compare_weather_windows`.
- Ужесточение `parseWorkPeriod` сломает существующие тесты, потому что текущие инструменты допускают положительные дробные `duration_hours`; новые строгие проверки должны быть отдельными.
- В существующих тестах MCP нужно обновить ожидания по списку инструментов, не ослабляя старые проверки.

## План совместимости

Добавить новые helper-функции и метод с узким применением. Сохранить поведение `OpenMeteoRiskService.assess` и существующих handlers, кроме добавления новой регистрации.
